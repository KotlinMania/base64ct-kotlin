Confirmed cause and implementation

The initial common/native source directories contained no Kotlin implementation.
All seven reachable commits lacked it. The template was not excluding an
existing common implementation. Baseline publication reproduced NO-SOURCE for
Android Native ARM64 followed by the missing artifact error (raw exit 1).

The checked-in upstream base64ct 1.8.3 is pure Rust, has no production crate
dependencies, and uses no C/FFI imports. Its unsafe sections concern byte-buffer
overlap and UTF-8 conversion. No C/JNI/N-API binding is required by this upstream
implementation. Existing unrelated FFI scaffold/configuration was preserved.

Manual source additions:

- 14 commonMain files: all 12 implementation modules, ByteSlice storage views,
  and concrete operation result types.
- Arithmetic standard padded/unpadded, URL padded/unpadded, bcrypt, crypt,
  PBKDF2 and SHA-crypt alphabets; SHA-crypt's byte order is preserved.
- Caller-owned and allocating encode/decode operations, in-place decoding,
  strict canonical-padding checks, lengths and distinct error diagnostics.

Kotlin adaptation details: methods use camelCase; required public Rust type
names and alphabet generics are retained. Concrete result payloads expose

it remains available for parity tests without warning suppressions. Arithmetic
structure is preserved; runtime timing characteristics have not been measured.
